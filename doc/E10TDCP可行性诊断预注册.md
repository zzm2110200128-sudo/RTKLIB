# E10：TDCP 可行性诊断预注册

> 状态：实施前冻结；日期：2026-09-05；分支：`ppp-tdcp-diagnostic`。
> 本阶段不修改 PPP，不把 TDCP 有效性作为既定结论。

## 1. 研究问题

手机 ADR 能否在固定三条开发轨迹上稳定提供相邻历元位移与接收机钟差增量，达到
足以值得设计 PPP+TDCP 的覆盖率、几何和误差水平？

## 2. 固定数据与禁止事项

仅使用既定三条开发轨迹。内部留出集和 Pixel 压力案例不读取、不调参。

真值只用于最后的离线位移误差评价，不参与观测配对、弧段划分、异常识别、权重或
阈值选择。诊断不修改 RINEX、PPP 配置、`src/ppp.c` 或现存结果。

## 3. 四项诊断

### D1 原始观测与时间一致性

- 观测身份固定为星座、Svid、载波频段、CodeType；同身份同 `utcTimeMillis` 只能
  有一条记录，重复/冲突单独报告；
- 相邻对按真实 `dt` 分组，不把“相邻保留记录”等同于严格 1 s；主范围为
  `0.5 <= dt <= 1.5 s`，其他间隔只描述；
- 不跨 `HardwareClockDiscontinuityCount` 变化；两端 ADR 均须 `VALID`，且均无
  `RESET`、`CYCLE_SLIP`；
- `HALF_CYCLE_REPORTED` 且未 `HALF_CYCLE_RESOLVED` 的记录单列，默认不进入
  full-cycle 主解；不得只凭 VALID 判为连续可靠；
- 核验 `ΔADR - (rate1+rate2)/2*dt` 的符号与单位，并列出时钟不连续附近样例。

### D2 可用覆盖率与几何

- 按设备、GPS/Galileo、L1/E1 与 L5/E5a 报告单条有效率、有效相邻对、连续弧
  历元数/时长和断档时长；
- 每个时间对报告可用信号数、唯一卫星数及系统构成；
- 离线设计矩阵使用真实星历/卫星位置。主模型估计三维位移、GPS 钟差增量和
  Galileo 相对钟差增量，共 5 个未知量；同时报告单钟差四未知量参考结果；
- 不满秩和条件数异常历元保留计数，不静默删除。

### D3 ADR—伪距率一致性

- 使用区间平均伪距率 `(rate1+rate2)/2*dt`，不使用单端 rate；
- 报告 signed diff 的中位数及 `|diff|` P50/P95/P99/最大值；
- 以同一时间对跨星中位数作为“共同项”描述，再报告去共同项后的单星差异；
- 固定描述阈值 `|centered diff| > 0.5/2/5 m`，不根据输出改阈值；
- 多星同向共同异常与单星异常分别计数，不能全部解释为周跳。

### D4 离线相邻位移可解性

- 不修改 PPP，在每个满秩相邻时间对上最小二乘估计位移与钟差增量；
- 异常筛选只能使用 D1 状态位和预注册的 D3 观测内部条件，不能看真值；
- 用相邻真值之差评价 ENU 位移，报告直接成功率、P50/P95/P99/最大值和条件数分箱；
- 同时计算零位移基线；如果可可靠构造，再加 Doppler-only 基线；
- 分设备、星座和频段报告，不用三轨迹合并均值掩盖单轨失败。

## 4. 进入 PPP+TDCP 的硬门槛

以下门槛必须由三条开发轨迹**分别**满足：

1. D1：主范围配对不存在身份歧义；所有进入求解的对均未跨硬件时钟不连续，且
   状态判据可复现；
2. D2：至少 80% 的真值相邻 1 s 区间具有双系统五未知量满秩 TDCP 解；条件数
   P95 小于 1000；
3. D3：去时间对共同项后，full-cycle 主集合 `|diff| P95 <= 0.5 m`、
   `P99 <= 2 m`，且 `>5 m` 比例不超过 1%；
4. D4：全部直接求解历元中，水平位移误差 `P50 <= 0.5 m`、`P95 <= 2 m`，
   直接成功率至少 80%，并且 P95 相对零位移基线改善至少 20%；
5. 不允许某一轨失败后用三轨合并指标通过，也不允许临时放宽半周、时间或异常阈值。

任一门槛失败时，结论为“当前严格口径不支持进入 PPP+TDCP”。可以报告失败原因，
但新的半周处理、单系统模型或阈值属于下一项重新预注册的问题，不能算本轮补跑。

## 5. 若通过后的实现边界

即使 E10 全部通过，也只获得进入实现设计的资格，不等于 PPP 精度必然改善。正式
融合需另行处理原始载波与 TDCP 同源、相邻差分共享观测造成的时间相关，不能把两者
作为独立观测重复计权；仍须默认关闭、OFF 逐字节回归，并与 SPP/B 完整时间轴比较。
