# E7b 一步 EKF 删组重算敏感性诊断（2026-09-04）

## 1. 研究问题

E7a 发现稳态相位验前创新量约 7–8 m，而单行边际预测创新标准差约 92–94 m；
但仅凭这个量不能断言相位对位置更新“权重趋零”。E7b 直接回答：在当前 B 配置的
一次 EKF 量测更新中，删除 code 或某一来源的相位后，位置更新会改变多少？

本步仍是**只读诊断**，不修改正式状态和结果，不是新算法实验。

## 2. 方法与口径

在 E7a 默认关闭的 `PPP_PHASE_DIAG` 代码内增加第二份历元级 CSV：
`PPP_PHASE_UPDATE_DIAG_OUT`（缺省 `phase_update_diag.csv`）。正式 `filter()`
完成后、状态回写前，从完全相同的预测状态 `x-/P-`、验前创新 `v`、设计矩阵 `H`
和观测协方差 `R` 出发，分别删去一组观测并额外调用一次 `filter()`：

1. 去 code，仅保留相位；
2. 去全部相位，仅保留 code；
3. 去原始 RINEX LLI 含 bit0 的相位；
4. 去原始 RINEX LLI 仅含 bit1（half-only）的相位；
5. 去原始 LLI 干净、但 RTKLIB 内部 GF/MW 等探测器置 slip 的相位；
6. 去原始与内部 slip 均干净的相位。

只保存最终通过验后检查的迭代。主指标：

- `dx_full`：正式完整量测的一步 ECEF 三维位置改变量；
- `gap_full`：完整更新位置与删组重算位置之差的三维模；
- `psig`：更新后位置协方差前三个对角元之和的平方根。

`gap_full` 是同一线性化点上的**删组敏感度**。由于观测通过共同先验协方差相关，
各组结果不可相加；删组重算也没有重新线性化、重新做验后粗差检查或沿时间轴继续运行，
因此它既不是因果贡献，也不能代替 E6a 端到端实验。

## 3. 核验

- 宏默认仍为 0，并允许以编译参数 `-DPPP_PHASE_DIAG=1` 临时启用；
- OFF 与 ON 构建均通过；
- ON 下三组 `.pos` 与各自 B 存档 SHA-256 **逐字节一致**；
- 三份历元 CSV 分别为 1183/1491/1165 行（含表头），每行固定 66 列；
- 对每个 PPP 成功历元，`nv=nphase+ncode`，且六种删组的实际行数均与
  `nphase/ncode/n_bit0/n_half/n_detector/n_clean` 推导值一致，零例外。

## 4. 稳态结果（300+s）

完整更新背景：

| 轨迹—设备 | 历元 | 完整 dx P50/P95 (m) | 位置 psig 更新前→完整 P50 (m) |
|---|---:|---:|---:|
| 07-14 Xiaomi | 882 | 5.082 / 13.002 | 66.265 → 46.946 |
| 12-08 Xiaomi | 1188 | 5.195 / 11.823 | 83.242 → 60.483 |
| 07-14 Samsung | 861 | 6.277 / 15.953 | 68.373 → 48.591 |

### 4.1 去 code 与去全部相位

| 轨迹—设备 | 删组后保留内容 | 保留行 P50 | gap P50/P95 (m) | 删组后 dx P50 (m) | 删组后 psig P50 (m) | ρ(gap,水平误差) |
|---|---|---:|---:|---:|---:|---:|
| 07-14 Xiaomi | 仅相位（去 code） | 6 | **2.980 / 7.441** | 2.666 | 55.513 | 0.149 |
| 07-14 Xiaomi | 仅 code（去相位） | 6 | 0.763 / 3.787 | 4.465 | 49.193 | 0.296 |
| 12-08 Xiaomi | 仅相位（去 code） | 6 | **2.527 / 6.153** | 3.038 | 69.104 | 0.053 |
| 12-08 Xiaomi | 仅 code（去相位） | 6 | 1.190 / 4.096 | 4.303 | 64.628 | 0.179 |
| 07-14 Samsung | 仅相位（去 code） | 5 | **4.019 / 10.206** | 2.616 | 59.489 | 0.064 |
| 07-14 Samsung | 仅 code（去相位） | 5 | 0.565 / 2.962 | 5.787 | 50.139 | 0.278 |

尽管 B 已将 code 名义方差大幅放大，去 code 对单历元位置更新的影响仍明显大于
去全部相位；只保留 code 时的位置协方差也比只保留相位时更接近完整更新。
这说明当前载波相位的大预测模糊度状态会吸收相当一部分相位创新，位置与钟差仍主要
依赖 code 提供单历元绝对约束。该结果不能反过来证明 code 精度好，也不否定 E6a：
E6a 是重新沿完整时间轴运行，三组最终结果方向不一致；E7b 只是固定线性化的一步敏感度。

### 4.2 按相位 slip 来源删组

| 轨迹—设备 | 删除相位组 | gap P50/P95 (m) | 删组后 psig P50 (m) | ρ(gap,水平误差) |
|---|---|---:|---:|---:|
| 07-14 Xiaomi | raw bit0 | 0.461 / 3.200 | 48.091 | 0.130 |
| 07-14 Xiaomi | raw half-only | 0.400 / 2.071 | 48.089 | 0.239 |
| 12-08 Xiaomi | raw bit0 | 0.938 / 3.872 | 62.751 | 0.147 |
| 12-08 Xiaomi | raw half-only | 0.542 / 2.309 | 62.011 | 0.072 |
| 07-14 Samsung | raw bit0 | 0.000 / 0.511 | 48.658 | 0.023 |
| 07-14 Samsung | raw half-only | 0.411 / 2.556 | 49.885 | 0.186 |
| 07-14 Samsung | detector-only | 0.076 / 0.822 | 48.808 | 0.061 |

Xiaomi 没有 detector-only/clean 相位；Samsung 的 clean 行也极少。raw bit0、
half-only 与 detector-only 的出现数量和卫星几何不同，故不能直接用 gap 大小给
三类观测排质量名次。当前只可确认：half-only 相位并非“完全没有进入状态更新”，
但也没有证据表明单独保留它会改善最终定位。

## 5. 可保留结论与下一步

1. E7a 的“大预测创新标准差”确实对应相位位置约束被独立模糊度状态削弱；
2. 当前 B 即使极重降权 code，单历元位置更新仍明显依赖 code，不能把 B 简化表述为
   “PPP 已经只靠相位定位”；
3. 相位仍提供非零边际作用，并进一步降低位置协方差，但其作用弱于完整 code 组；
4. 结果更支持把下一问题聚焦到**模糊度为何重建、重建时均值和方差如何变化**，而不是
   继续微调相位名义噪声或直接忽略全部 half-cycle 标志；
5. 下一步 E7c 先在 `udbias_ppp()` 做只读重建账本，精确区分新星/失锁/原始 bit0/
   half-only/GF-MW detector 等来源，并记录模糊度状态重建前后 `x/P`，再据此设计
   一个单变量连续性实验。

## 6. 复现

诊断构建需以编译参数临时启用：

```text
-DPPP_PHASE_DIAG=1
```

运行时设置：

```text
PPP_PHASE_DIAG_OUT=<E7a逐星CSV>
PPP_PHASE_UPDATE_DIAG_OUT=<E7b历元CSV>
```

分析脚本：

```text
python util/gsdc2022/analyze_phase_update_sensitivity.py \
  --case "LABEL|E7b_update.csv|B_cn0.pos|ground_truth.csv"
```

`--case` 可重复三次。完整开发集作为诊断集；内部留出集和 Pixel 压力案例未使用。
